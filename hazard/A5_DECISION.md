# A5 decision record: fitted hazard model (v1) as the simulator default

Status: accepted. Reviewed by T-lane (see agent/T_DECISION.md) and B-lane.

## Decision

- Default: `sim.config.SimConfig.hazard_model` is `hazard.v1.FittedHazardV1` and the new field `SimConfig.feature_fn` is `sim.scenario.v1_drive_features`. `contracts/contracts.py` and `hazard/v1.py` are unchanged: `FittedHazardV1` already satisfies the frozen `HazardModel` protocol, including the 720 h horizon.
- Why a new generator: the v0 generator (`sim.scenario.v0_drive_features`) builds five keys from Poisson draws tied to v0's saturation constants. v1 reads 28 value columns and the drive model name; given only those five keys it would see the other 23 as missing.
- v0 stays reproducible: the per-drive logic of `sample_fleet` moved, unchanged, into `v0_drive_features`, and `sample_fleet(..., feature_fn=v0_drive_features)` is its default. For 40 fixed (seed, level, spread) cases the feature dicts, `Fleet.pairs` and `Fleet.interval_fail_prob` are equal to the values captured before the change (`sim/golden_v0_fleet.json`, `sim/test_scenario_features.py`). `sim.config.v0_config()` returns a `SimConfig` with `HeuristicHazardV0()` and `v0_drive_features`.
- Empirical table: `python -m hazard.build_fleet_features` writes `sim/fleet_features_v1.json` from the train split only (`hazard.fit_v1.select_rows` with `TRAIN_SPLIT`; the paths are the `hazard.fit_v1` constants). Per drive model and value column it stores up to 2000 values (uniform sample without replacement, `SAMPLING_SEED = 20220501`) from `label == 0` rows ("healthy") and from `label == 1` rows ("failure"), a structural-missing flag, and the model's share of train drives. JSON was chosen because the file is 2.0 MB, loads with the standard library and diffs in git.
- Structural missingness: a (model, column) is flagged when at least 99.9% of that model's train rows have no usable (finite after float32 narrowing) value. In the built table the flagged cells are `smart_187_raw`, `smart_187_raw_diff7d`, `smart_187_raw_diff30d` and `smart_188_raw_diff7d` for TOSHIBA MG07ACA14TA (missing fraction 1.0); no other model has a flagged column. The generator omits those keys for that model at every level.
- Realized counts: every other (model, column, cell) holds the full 2000 values, so no cell is below the cap.
- Model shares (train drives): ST12000NM0008 14,165 (0.2187), ST4000DM000 13,258 (0.2047), ST8000NM0055 10,340 (0.1596), TOSHIBA MG07ACA14TA 27,005 (0.4169).
- Drive generation: each drive draws its model once with those shares. For each non-flagged column, with probability equal to the drive's degradation level (the existing fleet level plus per-drive spread, in `[0, 1]`) the value is drawn uniformly from the model's failure pool, otherwise from its healthy pool; an empty pool is replaced by the other. No column is special-cased. The returned dict holds the value columns and `model`, not the `_missing` flags, which `hazard.v1.build_feature_frame` derives.
- Call sites: `RecoveryEnv.reset` passes `config.feature_fn` to `sample_fleet`. `stress_config()` without a `base` is pinned to `v0_config()` (v0 hazard and feature function), independent of the new default. Existing tests were changed to construct their configuration with `v0_config()`: `sim/test_recovery_env.py`, `baselines/test_baselines.py` (and, for default configurations built inside `baselines/`, an autouse fixture in `baselines/conftest.py` that replaces the `SimConfig` name in `baselines.evaluate`, `baselines.policies` and `sim.recovery_env` with `v0_config`), and the latency-constant reads in `data_pipeline/tencent/build_profiles.py` and its test.
- Measurement script: `python -m sim.measure_defaults [--hazard v0|v1] [--seeds N] [--profiles ...]` reproduces the method of the `sim/LIMITATIONS.md` section 9 table for any `SimConfig`.

## Limits

- Values of the 28 columns are sampled independently per column from real marginal distributions, not jointly. A drawn drive does not reproduce the relationships between a drive's own columns on the same day (a level and its 7- and 30-day differences, the SMART 9 age and the other columns), and the model names within one group are drawn independently, so a group mixes drive models.
- The generator never emits a missing value except for the structurally missing columns: non-finite and NaN values are excluded from the pools, so the `_missing` flags that v1 sets are 1 only for those columns. Real timelines also have missing values elsewhere (for example the difference columns in a drive's first days).
- `sim/LIMITATIONS.md` section 9 (violation fraction by constant action and profile) is the v0 table and has not been regenerated under the v1 default. `python -m sim.measure_defaults` regenerates it (add `--hazard v0` for the v0 comparison). The same applies to any baseline or policy figure produced before this change with the `SimConfig` default, which was v0.
- Group hazard spread (ad-hoc check, 60 v1 fleets and 300 v0 fleets per level, spread 0.15; group hazard per year): at level 1.0 the v1 fleets have mean 3.07, 10th to 90th percentile 0.43 to 6.39, maximum 10.8, and the v0 fleets mean 1.73, 1.61 to 1.83, maximum 1.90. At level 0.0 the v1 fleets have mean 0.20, 0.09 to 0.30, maximum 1.32 (v0: 0.23, 0.21 to 0.26, maximum 0.33). Under v1 the level sets only the mixture probability between pools, so fleets at the same level differ widely in hazard, and a level of 0 is not a guaranteed low-hazard group.
- `sim/fleet_features_v1.json` (pools, structural flags, model shares) is exactly as current as the train split it was built from. A change of the A1 window or models, of the A2 labels or split, or of the value columns requires `python -m hazard.build_fleet_features` to be run again; `sim.scenario.load_fleet_table` does not compare the table with the fitted artifacts, and the test that compares the table's columns and categories with `hazard/artifacts/v1/meta.json` runs only when the artifacts are present.
- `SimConfig()` constructs `FittedHazardV1`, which reads `hazard/artifacts/v1/` (about 218 MB, not in git). On a checkout without the artifacts, `SimConfig()` without an explicit hazard model raises; `v0_config()` does not need them. Tests that need the artifacts are skipped when they are absent.
- Cost: a v1 call takes about 80 ms per drive, so a reset (nine drives) takes about 0.7 s, against well under a millisecond for v0. Loading the artifacts takes about 2 s per process.
- The failure pool holds all `label == 1` rows (the 30 days before a failure), so "failure-day" values are those of drives within 30 days of failing, not only values on the day of failure. The healthy pool holds all `label == 0` rows, including the rows of drives that fail later than 30 days after.
- The sampled values are stored as shortest float32 decimal representations; v1 narrows its inputs to float32, so the model input is the same.
- Features are fixed for the whole episode, as before.
